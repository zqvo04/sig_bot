# 사전등록: M1 — 방향-정렬 Taker Slope (ts_align)

> **상태:** 사전등록(pre-registration). 작성일 **2026-07-16**. 이 문서는 *새 데이터를 보기 전*
> 가설·임계 후보·성공 기준을 고정하기 위한 것이다. 데이터를 본 뒤 임계를 고르는 cherry-pick을
> 금지한다(CLAUDE.md §1·§3). 판정 결과가 어떻든 이 문서는 수정하지 않고, 판정은 하단 로그에 append한다.

## 1. 배경 · 가설

**진단 근거(탐색적, hypothesis-generating):**
- 두 페이퍼 트레이딩 로그(Base N=551 / Shadow N=1,256, ex-PEPE) 진단에서 시스템 전반의
  병목은 "신호 절반이 진입 직후 스탑 부근까지 역행(MAE>0.9R), 그중 96%가 패배"인 **진입 방향
  정확도(W3)** 로 확인됨.
- `ts_align = Taker Slope × dir`(dir: LONG=+1, SHORT=−1)로 정의한 **방향-정렬 taker 기울기**가
  Shadow 표본에서 롱·숏 **양방향 대칭으로** 결과를 분리:
  - 상위 절반 기대값 −0.110R vs 하위 절반 +0.094R (Mann-Whitney LONG p=0.030 / SHORT p=0.014),
    4분위 단조 감소.
  - Base(N=240)에서 **부호는 동일 재현**(−0.088 vs +0.036)이나 표본 부족으로 유의 미달.

**해석(기전 가설):** 진입 방향으로 taker 흐름이 *이미 강하게 가속·쏠린 뒤* 진입 =
추격(late/chase entry) → 즉시 역행 확률 상승. 즉 `ts_align` 상위 = W3(즉시 역행군)의
**사전(ex-ante) 식별자** 후보.

**정직성(이 근거의 지위):** 위 p값은 **데이터를 본 후 발견**한 것이다. 본 사전등록이 검증으로
간주할 수 있는 것은 *오직 미래(신규) 데이터* 에 대한 결과뿐이며, 기존 표본의 p값은 탐색적 통계로
강등해 취급한다. Base 유의 미달·부호만 재현이라는 한계도 그대로 인정한다.

## 2. 측정 대상 (측정-우선, 게이트는 검증 후 — §3)

- **측정량:** `ts_align = Taker Slope × dir`. Taker Slope는 이미 전 신호에 컬럼 적재 중
  (`fetch_taker`, 8×5m 봉 매수비율 최소제곱 기울기). **신규 수집 0** — 기존 컬럼 2개
  (`Taker Slope`, `Direction`)로 오프라인 유도.
- **자기정규화(§6):** 게이트 임계는 절대 기울기 값이 아니라 **자기분포 백분위**로만 다룬다.
- **데이터 위생:** taker 매수/매도 부호 수정(2026-06-23, `ee9fecd`)이 스캘핑 피처 수집 시작
  (2026-06-26, `dae3e8d`)보다 **선행** → 적재된 `Taker Slope` 전량이 수정 후 데이터.
  부호 오염 없음.
- **결측 정책:** `Taker Slope`가 None인 행은 코호트에서 제외(라이브 동작 영향 0). 게이트 승격
  시점의 불변 규칙: **게이트 평가에서 피처 None = 무조건 PASS(inert)** — 데이터 장애가 신호
  차단으로 전이되지 않는다.

---

## 3. 임계 후보 (범위 고정 — argmax 탐색 금지)

- **P_veto ∈ [80, 90] 백분위** (ts_align 자기분포 상위 꼬리 차단).
- **주 검증점 = P_veto 85 단일점.** 80·90은 **강건성 확인용**(결론이 임계에 민감하면 기각).
- 리포트의 4분위 코호트에서 **Q4(상위 25%)** 는 이 꼬리의 *거친 프록시*다. 정밀 P_veto 검정은
  판정 시점에 별도 실행한다.
- **금지:** [80,90] 격자 위를 훑어 기대값이 가장 좋은 점을 고르는 행위. 사후 미세조정 금지.

## 4. 성공 기준 (게이트 승격 = 아래 **전부** 충족)

판정 데이터: **2026-07-16 이후 신규 축적분만.** (그 이전 데이터는 가설 생성에 사용됨 →
검증 재사용 금지.) 라이브+Shadow 병용 가능(둘 다 동일 채점기).

- [ ] **G1 표본:** 상위 코호트(ts_align > P_veto)와 대조군 각각 **n ≥ 30**. 방향별로도
      LONG n≥30 ∧ SHORT n≥30.
- [ ] **G2 워크포워드 50/50:** 시간순 앞/뒤 두 구간 **모두에서** 상위 코호트 기대값 <
      하위 코호트 기대값. 한 구간만 성립하면 기각.
- [ ] **G3 롱/숏 대칭:** LONG·SHORT 각각에서 상위>하위 기대값 열위가 **동일 부호**.
      부호가 반대면(비대칭) 방향 편향 위험으로 기각.
- [ ] **G4 통계:** 상위 코호트 기대값 부트스트랩 **95% CI 상한 < 전체 평균 기대값**.
      (상위 꼬리가 전체 대비 유의하게 나쁨을 요구.)
- [ ] **G5 반사실 무결성:** 게이트로 차단될 셋업을 `_shadow()` 경로로 Shadow 적재 →
      would-be 기대값이 실제로 ≤ 0(승자 제거=FN 아님)임을 확인.

**하나라도 미달 = NO-GO.** NO-GO는 사유와 함께 로그에 기록하고, 재시도는 *또 다른 신규
데이터* 로만 한다(같은 데이터 재검정 금지).

## 5. 승격 시 게이트 형태 (청사진 — 지금 구현 안 함)

```
ENTRY = L ∧ F ∧ S ∧ RR ∧ ¬VETO
VETO += (ts_align is not None) ∧ (percentile(ts_align) > P_veto)
미러: LONG·SHORT 모두 "자기 방향 정렬의 상위 백분위" 정의 → 부호 대칭 자동 충족
```
- 토글 `ORTHO_TS_ALIGN_VETO_PCT`, 기본 `100`(= 아무것도 차단 안 함 = inert). 단일 env-var 롤백.
- 봇 무상태 원칙: 백분위 산출은 오프라인. 승격 시 P_veto에 대응하는 **raw 기울기 임계**를 env-var에
  박제하고, 분기별 재캘리브레이션을 이 문서 개정으로 사전등록.
- **가중합 스코어링 금지**(피처당 독립 VETO 1개). 가중치는 argmax 표면이 된다.
