## 2. 정의 (전부 스케일프리, R 단위)

### 2.1 R·방향·청산유형
| 기호 | 정의 | 출처 |
|---|---|---|
| `R_gross` | `PnL%/100 × Entry / R Dist` (V3·V4 공통 재계산) | `ortho_report.load()` |
| `u` | `R Dist / Entry` (손절폭 비율) | 〃 |
| `d` | LONG=+1, SHORT=−1 | `Direction` 열 |
| `x` | 청산유형 ∈ {TP, SL, TIME, BE} | **§2.5** |
| `cost_R` | `cost_frac / u` = `cost_frac × Entry / R Dist` | Q4 |
| `Net` | `R_gross − cost_R − fund_R` | |

V4는 `Gross R` 열과 `R_gross` 교차검증(|Δ|>0.01 건수·최대차 보고). `Net R`/`Estimated·Realized Cost R` 열은 SIM_COST_0 산물이므로 **사용 금지**.

### 2.2 시나리오 A (계산·판정용, 낙관 = 비용 하한)
| 구성 | 비용 (가격 대비 분수) |
|---|---|
| 진입 | maker **0.0002** — 신호 Entry 가격에 100% 체결 가정, 스프레드 미지불(패시브) |
| 청산 TP | maker **0.0002**, 스프레드 0 |
| 청산 SL / TIME / BE | taker **0.0005** + 반스프레드 `h = 0.5 × tickSz / Entry` (틱 바닥) |
| 슬리피지 | 0 |
| 펀딩 | §2.4 |

→ `cost_frac_A(TP) = 0.0004` · `cost_frac_A(SL|TIME|BE) = 0.0007 + h` · `cost_R = cost_frac / u`.
수수료율 **미검증**(2차 출처, `facts_okx.md` §3). VIP0 가정(Q3). `tickSz`는 현재값 고정 가정(기간 내 불변 — 미검증):

| 심볼 | BTC | ETH | HYPE | SOL | SUI | XRP |
|---|---|---|---|---|---|---|
| tickSz | 0.1 | 0.01 | 0.001 | 0.01 | 0.0001 | 0.0001 |

### 2.3 시나리오 B·C (보조 민감도 — 판정 불참)
| 시나리오 | 정의 | `cost_frac` |
|---|---|---|
| B | 진입·청산 모두 taker 0.0005 + 반스프레드 `h` (TP 포함) | `0.0010 + 2h` |
| C | B + **SL·BE 청산에 불리 슬리피지 0.05 R** (= `0.05 × R Dist`; 심볼 중립·스케일프리, 사전 1점 고정, 튜닝 없음) | B + `0.05R` (SL·BE만) |

C의 0.05R은 근거가 약한 보수 가정이다(OKX 과거 호가 이력 없음, `facts_okx.md` §4). 해석은 "방향성 확인"뿐이며 최적 비용을 찾는 것이 아니다.
**실전 판정에 A 사용 금지**(마스터 §3 Phase 6). B/C도 실측 비용으로 대체되기 전까지 실전 근거 아님.

### 2.4 펀딩 `fund_R = d × Σ rate(t_f) / u`
- 보유창 `[S, E]`: `S = Signaled At`, `E = Resolved At`, 없으면 `S + Bars To Exit × 15m`. 시각은 KST 입력 → UTC 변환(−9h).
- 정산시각 `t_f ∈ {00,08,16 UTC}` 중 **`S < t_f ≤ E`** 인 것만 합산. 롱은 양(+) 율을 지불(비용), 숏은 수취. 포지션가치는 Entry 근사(정산시점 마크가격 무시).
- 율 출처: OKX `funding-rate-history`(실현 `realizedRate` 우선, 없으면 `fundingRate` — `realizedRate` 필드는 2026-11-03 BTC 응답에서 존재 확인). 가용 구간 **2026-08-03 16:00 UTC ~ 2026-11-03 08:00 UTC (심볼당 276건, 8h 고정)**.
- **V4**: 전량 커버. 보유창이 걸친 정산 시각 중 캐시 결측이 **1건이라도 있으면 중단**(0건이어야 함).
- **V3**: 펀딩 = **확인 불가 → 0으로 설정**, 아래를 반드시 병기:
  1. 보유창이 정산시각을 1회 이상 포함하는 V3 거래 비율(심볼별·전체).
  2. 민감도 경계: `±n_cross × max|rate_심볼| / u` (max|rate|: 92일 창 관측 최대, BTC .00375 · ETH/SOL/XRP .0075 · HYPE/SUI .01). V3 Net_A를 `[Net_A − 경계, Net_A + 경계]` 구간으로 병기. 92일 창이 V3 기간을 대표한다는 보장 없음(미검증).
- 경계 일치(`t_f == S` 또는 `t_f == E`) 거래 수를 보고(포함 규칙 민감도 가시화).

### 2.5 청산유형 `x` 복원 (전용 열 없음)
Notion 스키마에 청산사유(TP/SL/TIME/BE) 전용 열 **없음**. `Status`는 WIN/LOSS뿐(TIMEOUT 옵션은 있으나 해소 행에 없음). 청산등급은 `Note`의 `|` 구분 토큰(`R=±x | GRADE | MFE../MAE..`)에서 `ortho_report._grade()`로 파싱. 순서:
1. `Note` 토큰 ∈ {TP,SL,BE,TIME} → 채택. 기록률(코호트별)을 보고.
2. 미기록 시 **사전 고정 추론** (이 순서, 1회만): `Status=WIN` 이고 `|R_gross − RR| ≤ 0.05` → TP · `Status=LOSS` 이고 `|R_gross + 1| ≤ 0.05` → SL · 나머지 → TIME(taker 취급).
3. 추론 비율 > 5%이면 보고서 결론에 경고. 추론 건은 per-exit-reason 표에서 `(추론)` 접미로 분리.

## 6. 판정 규칙 — 마스터 §1.1 비대칭 표 그대로 (V4 Net_A, 판정 CI)

| 판정 CI | 판정 |
|---|---|
